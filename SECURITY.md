# Security and privacy

## Public-repository rule

Commit only schemas, fictional examples, documentation, and deterministic validation code.

Do not commit:

- Exact street addresses, building access instructions, or precise household location data.
- Real grocery history or dietary information that the user considers sensitive.
- Retailer account identifiers, loyalty numbers, receipts, order history, or saved carts.
- Credentials, cookies, session tokens, API keys, one-time codes, or payment information.
- Screenshots or exports from authenticated retailer accounts.

## External access

Use public product pages for research when they are sufficient.
If checkout-level or member-only data is necessary, keep authentication under direct user control and obtain separate action-time approval before any account change.

## Reporting a problem

Open a private security report with the repository maintainer.
Do not include live credentials or personal purchase data in a public issue.
